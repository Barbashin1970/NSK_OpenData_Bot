# Разбор: ответ /ask не ждёт обновления данных OSM (BEKLOG № 12)

Дата: 2026-11-17. Разбор написан до правок кода.

## Сводка

1. **Что не так.** `/ask` по теме из OpenStreetMap проверяет срок данных и, если он вышел,
   сам перекачивает тему через Overpass — человек ждёт. Если Overpass данных не отдал, тема
   остаётся устаревшей, и следующий запрос ждёт снова.
2. **Замер.** 17.11.2026 «сколько парковок по районам» не ответил за 90 с
   (`curl --max-time 90`); по `/topics` с 20.08 не обновлялись парковки, детские сады,
   спортплощадки, с 15.10 — аптеки. В снимке демо-копии по таймауту выпадали также больницы
   и камеры по районам.
3. **Где.** Три места в `src/routes/data.py` одного вида «устарело → скачать → записать»:
   общие OSM-темы (`_handle_osm_topic`), камеры (`topic == "cameras"`), медицина
   (`topic == "medical"`).
4. **Решение.** Общий помощник `src/stale_refresh.py`: данные есть — ответ сразу из кэша,
   обновление в фоновом потоке; данных нет — обновление в запросе, как раньше; не больше
   одного обновления темы одновременно; после неудачи — пауза 30 минут.
5. **Что не меняется.** Явное обновление (`POST` с загрузкой OSM) остаётся синхронным:
   его запускает человек и ждёт результат.

## Решения

| # | Решение | Почему |
|---|---|---|
| О-1 | Устаревшие данные отдаются сразу, обновление — в фоне | Устаревшие на неделю парковки лучше, чем 90 с ожидания и пустой ответ |
| О-2 | Данных нет совсем — качать в запросе | Отвечать нечем; так было и раньше |
| О-3 | Одно обновление темы за раз | Сейчас каждый запрос к устаревшей теме запускал свою закачку — Overpass получал десятки одинаковых запросов |
| О-4 | После неудачи 30 минут не пробовать | Зеркала Overpass, недоступные с Railway, не станут доступны через минуту; без паузы каждый запрос снова ждёт |
| О-5 | Путь к базе и город фиксируются в момент запроса; если город сменился, пока качали, запись не делается | Прокси Академгородка на время запроса переключает город — фоновая запись не должна попасть в чужую базу |

## Чего не делаем сейчас

| Не делаем | Почему |
|---|---|
| Обновление по расписанию для OSM-тем | Хватает обновления по первому запросу после срока; расписание — отдельная задача |
| Причину неудач Overpass с Railway | Видна в `/osm/diagnose`; здесь — только чтобы неудача не держала ответ |
| То же для отключений и экологии | Их источники отвечают за секунды, и для отключений уже есть замок |

## Закрыто

- **О-1…О-5** — `src/stale_refresh.py` (`refresh_if_stale`), подключён в трёх местах
  `src/routes/data.py`: `_handle_osm_topic`, камеры, медицина. Явная загрузка OSM (`POST`)
  не тронута.
- **Проверки** — `tests/test_stale_refresh.py`, 8: свежие не обновляются; при кэше ответ сразу,
  закачка в фоне, вторая не запускается; без данных — в запросе; после неудачи (0, None,
  исключение) — пауза, по её окончании снова пробуем; `/ask` по камерам с закачкой в 3 с
  отвечает без ожидания — на прежнем `data.py` тот же запрос шёл 3,3 с и проверка падала;
  в `get_ask` не осталось синхронной закачки.
- **На проде** — проверить после выкатки: «сколько парковок по районам» отвечает сразу
  (данные с 20.08 с пометкой «устарел»), а в следующем снимке демо-копии карточки детских
  садов, парковок и спортплощадок не прячутся.
