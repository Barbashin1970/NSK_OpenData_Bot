# Разбор: демо-копия лендинга СИМА на GitHub Pages

Дата: 2026-11-17. Разбор написан до правок кода. Образец — PROMPT-Professor
(`.github/workflows/pages.yml`, `tools/dlya-pages.py`) и навык vault `publish-github-pages`.

## Сводка

1. **Зачем.** Railway из российских сетей без VPN не открывается (замер 05.11.2026 в отчёте
   РАГРАФ, п. 7.2), а `*.github.io` открывается. Для показа в мэрии нужен дубль лендинга
   по адресу `https://barbashin1970.github.io/NSK_OpenData_Bot/`. Railway остаётся основным.
2. **Главная трудность.** Лендинг — не статика: каждый блок берёт данные у FastAPI.
   Браузер мэрии не достучится до Railway и с github.io, значит, дублю нужен **снимок
   ответов API**, а не живые запросы.
3. **Решение.** GitHub Action раз в час забирает с Railway ответы для всего, что показывает
   лендинг (серверы GitHub до Railway достают), и публикует их на Pages вместе с копией
   страницы. В копии прослойка подменяет `fetch`: адрес запроса → файл снимка.
4. **Что выключено** (просьба заказчика): «Данные», «Задачи» и прочие страницы управления,
   задачи на табло мэра, отправка отзывов и ответов, обновления данных, выбор города.
5. **Что нельзя публиковать:** ключ карты 2ГИС (`/mapgl-key`) — в статике карта не включается.
6. **`index.html` для Railway не меняется** — всё делает скрипт копии, как в PROMPT-Professor.

## Схема

```
GitHub Actions (раз в час, при правке лендинга, вручную)
  ├─ configure-pages@v6 — Pages не включены → остановка, к Railway не обращаемся
  ├─ scripts/dlya_pages.py --api https://nsk-opendata-bot.up.railway.app
  │    ├─ снимок: GET к Railway по списку адресов → _pages/api/<ключ>.json
  │    │  (подпись SIMA-pages-snapshot — сервер не пишет эти /ask в журнал запросов)
  │    ├─ копия index.html: прослойка fetch сразу после <meta charset>, приставка
  │    │  /NSK_OpenData_Bot к /static/, ссылки на страницы управления выключены
  │    └─ самопроверка: адрес от корня без приставки, charset не в начале, нет важного
  │       снимка → остановка
  └─ upload-pages-artifact@v5 → deploy-pages@v5
Браузер в мэрии → barbashin1970.github.io/NSK_OpenData_Bot/ → только файлы, без Railway
```

## Решения

| # | Решение | Почему |
|---|---|---|
| Р-1 | Снимок ответов API, а не прокси к Railway | Прокси на github.io невозможен, а прямые запросы к Railway из России не проходят |
| Р-2 | Ключ файла = FNV-1a от канонического адреса: путь + параметры, раскодированные и отсортированные | Страница строит адреса сама (`encodeURIComponent`, порядок параметров); каноника снимает различия Python и JavaScript |
| Р-3 | Список адресов снимка берётся из самого `index.html`: готовые запросы, шаблоны с районом, чипы ролей | Список не разойдётся со страницей при её правке |
| Р-4 | Запрос не из снимка → понятный ответ «нет в демо-снимке», не падение | Свободный текст в строке запроса статика не обслужит |
| Р-5 | Ссылки управления → `#demo-off` с подсказкой; `window.open` и POST перехвачены прослойкой | Просьба заказчика: «Данные» и «Задачи» неактивны |
| Р-6 | Важные снимки (`/api/city-config`, `/power/forecast`, `/ecology/status`, отключения сейчас) не получены → сборка останавливается | Лучше прошлая рабочая публикация, чем новая пустая |
| Р-7 | Версии действий проверены по API релизов на 17.11.2026 | Урок PROMPT-Professor: `deploy-pages@v4` не находил артефакт нового `upload-artifact` |
| Р-8 | Прослойка вставляется сразу после `<meta charset="UTF-8">`, а не после `<head>`; самопроверка требует charset в начале файла и до прослойки | Найдено проверкой в браузере: вставка перед charset отодвигала его, и без charset в заголовке ответа начало страницы читалось как windows-1251 — кракозябры в плашке и ответах прослойки |
| Р-9 | Значения по умолчанию сервера (`/ask`: `offset=0`, `page_size=20`) в ключ не входят — один словарь в Python и в прослойке | `ask()` шлёт `/ask?q=…`, листалка — с параметрами страницы; ответ сервера один и тот же, снимать дважды незачем |
| Р-10 | Сервер не пишет в журнал запросов `/ask` с подписью `SIMA-pages-snapshot/` (`src/routes/data.py`, `SNAPSHOT_UA`) | Снимок раз в час — 189 адресов `/ask`, около 4 500 служебных строк в сутки в `query_log`, из которого считаются `/api/query-stats` и история запросов |
| Р-11 | Готовые запросы берутся из страницы в обеих кавычках: `askNow`, `setQuery`, `q:` | Найдено на живом сайте: набор примеров ролей записан как `{q: "…"}`, и 25 из 43 примеров, в том числе видимые на табло чипы, отвечали «нет в демо-снимке» |
| Р-12 | Ответ с данными API 2ГИС (поле `source` с «2GIS») в снимок не идёт — `not_stored_2gis` в `_snapshot.json` | Правила 2ГИС: маршруты и справочник — только проброс в реальном времени. Уровень Яндекс.Пробок в `/traffic-index` хранится с временем и ссылкой на источник, как на основном сайте, только обновляется раз в час |
| Р-13 | Запросы, которые страница строит на лету, разворачиваются по тем же правилам: шаблоны `${t.name}`, `${_d1.prep}`, `${_tr1}`/`${_tr2}`, `${esc(dist)}`, метро и аэропорт из конфига; второй шаг — кнопки «Район:» под каждой таблицей из снимка (порты `_distPrep`, `_distQuerySuffix`, `_stripDistrictFromQuery` сверены с оригиналами в node); номера линий метро — из ответа. Перед этим проба: по карточке на тему, не ответившая за 30 с тема выпадает | Живой сайт 17.11: карточки «покажи …», метро, аэропорт, районы — 12 из 21 кнопки страницы и 50 из 76 кнопок в ответах давали «нет в демо-снимке». Проба нужна, потому что зависшие темы (BEKLOG № 12) держали бы сборку и нагружали Railway |
| Р-14 | Кнопка, чьего запроса нет в снимке, прослойкой прячется; при промахе в строке поиска — до пяти похожих сохранённых запросов, по ним можно нажать | Лучше меньше кнопок, чем отказ по клику. Когда сервер починят, кнопки вернутся сами — решает снимок, а не список |
| Р-15 | Игра «Пятнашки» и пользовательские отчёты (МТС, аварийные службы) в демо выключены: кнопки скрыты, вызов — плашка, `/custom-reports` прослойка отвечает «нет» без запроса в сеть | Просьба заказчика 17.11: отчёты давали 404, игра на показе в мэрии не нужна |
| Р-16 | Раз в час обновление запускает сам сервер Railway — `workflow_dispatch` по API GitHub (`src/pages_dispatch.py`, токен в `GITHUB_PAGES_TOKEN`); расписание GitHub остаётся запасным | 17.11 за шесть часов после подключения GitHub не сделал ни одного планового запуска (workflow активен, ветка по умолчанию `main`, сбоев Actions нет) — только запуски от слияний. Документация GitHub: плановые запуски при нагрузке задерживаются и выпадают |

## Разрывы

| # | Разрыв | Важность | Закрывает |
|---|---|---|---|
| 1 | Лендинг не открывается без VPN | несущий | весь разбор |
| 2 | Страница ходит в API от корня — на Pages это корень домена, а не `/NSK_OpenData_Bot/` | несущий | прослойка + приставка |
| 3 | Ключ 2ГИС попал бы в публичный снимок | несущий (безопасность) | `/mapgl-key` не снимается, прослойка отвечает `available: false` |
| 4 | Страницы управления и отправка данных в демо | важный | Р-5 |
| 5 | Данные устаревают | важный | обновление раз в час + плашка «данные на …» |

## Чего не делаем сейчас

| Не делаем | Почему |
|---|---|
| Страницы «Данные», «Задачи», Студию, презентацию, видеостену | просьба заказчика: только выдача данных |
| Произвольные запросы в строке поиска | без сервера их не на чем считать; снятые готовые запросы работают |
| Карту 2ГИС | ключ нельзя публиковать; ограничение ключа по домену — отдельный вопрос |
| Замену `cdn.tailwindcss.com` локальной копией | заказчик проверил демо 17.11.2026: оформление грузится, работает быстро. `cdn.tailwindcss.com` стоит за Cloudflare, github.io — за Fastly; если оформление пропадёт, скачивать скрипт при сборке и класть рядом со страницей |
| Снимки страниц таблицы дальше первой | пагинация по каждому запросу умножит снимок в разы |

## Инструкция: что сделать на GitHub (один раз)

0. Репозиторий должен быть **публичным**: на бесплатном тарифе Pages для приватных
   недоступен. Ключей в git нет (`data/api_keys.json` и `.env` в `.gitignore`, в истории
   не появлялись — проверено 17.11.2026).
1. **Settings → Pages → Build and deployment → Source: GitHub Actions.** Без этого первый
   запуск упадёт на `configure-pages` («Get Pages site failed») — теперь это первый шаг,
   и к Railway такой запуск не обращается.
2. Слить ветку с workflow в `main`: запуск начнётся сам. Или **Actions →
   «Демо лендинга на GitHub Pages» → Run workflow**. Railway выкатывает новую версию
   несколько минут; если первый снимок успеет раньше, одна порция (~190 строк) попадёт
   в журнал запросов — дальше сервер их не пишет (Р-10).
3. Если запуск упал с «Branch "main" is not allowed to deploy to github-pages» —
   **Settings → Environments → github-pages → Deployment branches** → добавить `main`.
4. Проверить: `https://barbashin1970.github.io/NSK_OpenData_Bot/` — **регистр в пути
   как в имени репозитория**. Первые 1–2 минуты возможен 404; Pages кэширует до 10 минут.
5. По желанию — **Settings → Secrets and variables → Actions → Variables → `SIMA_API`**,
   если адрес Railway сменится. По умолчанию — `https://nsk-opendata-bot.up.railway.app`.
6. Расписание GitHub отключает через 60 дней без коммитов в репозиторий — тогда снимок
   перестанет обновляться; включается обратно кнопкой на вкладке Actions.
7. **Ежечасное обновление с Railway (Р-16).** GitHub → Settings (аккаунта) → Developer
   settings → Personal access tokens → **Fine-grained tokens** → Generate new token:
   Repository access — **Only select repositories → NSK_OpenData_Bot**; Permissions →
   Repository permissions → **Actions: Read and write**; срок — на выбор (по истечении —
   новый токен). Затем Railway → сервис → **Variables → `GITHUB_PAGES_TOKEN`** = токен.
   В журнале сервера раз в час: «pages_dispatch: обновление демо-копии запущено».
   Обновить немедленно — **Actions → «Демо лендинга на GitHub Pages» → Run workflow**.

## Закрыто

Проверено локально 17.11.2026: копия собрана с Railway в подпапку и раздана
`python3 -m http.server` (как Pages — сайт в `/NSK_OpenData_Bot/`), затем открыта в Chrome
без окна через протокол DevTools: роль мэра, клики, запросы, журнал сети. Сценарий проверки
лежит вне репозитория, в рабочей папке сессии; его шаги перечислены ниже.

- **Снимок:** `python3 scripts/dlya_pages.py --osnova /NSK_OpenData_Bot --vyhod … --api
  https://nsk-opendata-bot.up.railway.app` → «снимков 312 из 312 (2.3 МБ) за 33 с,
  пропущено 0; адресов без основы нет». Первая сборка без потоков шла больше 10 минут —
  добавлены 6 потоков, таймаут 45 с, две попытки.
- **Разрыв 2 (адреса от корня):** запросов к сайту 29, мимо подпапки — 0.
- **Разрыв 3 (ключ 2ГИС):** `/mapgl-key` не снимается, прослойка отвечает `available: false`.
- **Разрыв 4 (управление):** ссылок управления выключено 4; клик по «Данные» не уводит со
  страницы и показывает плашку «недоступно».
- **Р-2 / Р-9 (ключи):** ключи Python и браузера совпали на 8 адресах из 8, в том числе
  `/ask?q=…` с параметрами страницы по умолчанию и без них.
- **Р-4:** готовый запрос «качество воздуха в городе» отвечен из снимка; произвольный —
  понятным ответом «нет в демо-снимке» (единственный 404 в журнале — этот, нарочно).
- **Р-8 (кодировка):** `document.characterSet` = UTF-8, кракозябр на странице — 0.
- **Табло мэра:** блок «прогноз на 2 недели» с бейджем режима и строкой «обещано →
  сбылось»; модалка «?» открывается, её текст сверен с кодом (ZHKH-KALIBROVKA-RAZBOR, K.3).
- **Внешние хосты:** `cdn.tailwindcss.com`, `cdn.jsdelivr.net`, `fonts.googleapis.com`,
  `fonts.gstatic.com` — их доступность без VPN не проверена (риск в «Чего не делаем»).
- **Проверки:** `tests/test_dlya_pages.py` — charset в начале и до прослойки (Р-8),
  ключ без параметров по умолчанию (Р-9), ключи Python и прослойки совпадают в node (Р-2),
  снимок не пишется в журнал (Р-10; на прежнем `data.py` падает).

- **Живой сайт** (слияние `181bbae`, запуск workflow № 1 — успех, снимок 312 из 312): та же
  проверка на `https://barbashin1970.github.io/NSK_OpenData_Bot/` проходит по всем пунктам;
  github.io отдаёт `charset=utf-8`, адрес в нижнем регистре — 404, `/mapgl-key` — 404.
  Заказчик проверил сам: «работает ожидаемо и быстро», обновление раз в час устраивает.
- **Р-11:** из 64 готовых запросов страницы в снимке 62. «Сколько парковок по районам» —
  сервер не отвечает и за 90 с (BEKLOG № 12); «аптеки в Центральном районе» — разовый
  таймаут, пока сервер обновлял данные, следующий снимок его заберёт.
- **Р-12:** ответов с данными 2ГИС в снимке нет: маршрутные ответы собираются из открытых
  данных мэрии, 2ГИС в них — только ссылка.

- **Р-13–Р-15** (сборка 17.11, локально): снимков 837 из 847 (3,9 МБ) за 294 с, кнопки
  «Район:» — 362 адреса; проба: «Детские сады» не ответили за 30 с. Обход видимых кнопок
  в браузере, роль мэра: на странице 24 запроса — нет в снимке 0 (было 12 из 25), в ответах
  160 — нет 0 (было 50 из 74); карточек наборов 23, все отвечают; игры и отчётов нет.

**Открыто:** BEKLOG № 12 закрыт 17.11 (`docs/OSM-OBNOVLENIE-RAZBOR.md`): после выкатки темы
отвечают из кэша сразу, и скрытые кнопки вернутся сами со следующим снимком (Р-14).
Ежечасный запуск с Railway (Р-16) заработает, когда на Railway появится `GITHUB_PAGES_TOKEN`.
