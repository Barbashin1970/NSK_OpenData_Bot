# Разбор: индексы жизни — «Водитель» и «Погодная нагрузка на ЖКХ»

Живой документ: пункты закрываются со ссылкой на коммит и проверку.

## Сводка

- 18.11.2026 индексы сведены с РАГРАФ (их `nsk-life-indices`):
  - «Водитель» — гололёд по влаге, а не по одной температуре (`9be181d`);
  - «Коммунальное напряжение» стало «Погодной нагрузкой на ЖКХ»: мороз и снегопад, без смога
    (`4decde6`, `life_indices_rules` 1.2).
- Сервер (`/life-indices`, `_compute_life_indices`) и табло (`computeLifeIndices`) считают
  одинаково. Это держат проверки `tests/test_life_index_driver.py`: сервер на Python, табло — node.
- РАГРАФ свёл своё правило с нашим `737481d` и нашёл три расхождения кода с нашими же текстами
  (С1–С3). Пересчёт `snow_impact` по нашему коду у них совпал на 1 352 сочетаниях.

## Разрывы

| № | Разрыв | Важность | Фаза |
|---|---|---|---|
| С1 | Подсказка и регламент 1.2 говорят «мороз по ночному минимуму», а код берёт наименьшую **текущую** температуру по районам | высокая: подпись не совпадает с расчётом, балл расходится с РАГРАФ | И.1 |
| С2 | «Критическая» недостижима: наибольшая сумма 4 (мороз) + 3 (снег) = 7, а уровень начинается с 8 | средняя: табло обещает уровень, которого не бывает | И.2 |
| С3 | Нет прогноза — `snow_impact` = 0 (`default=0`, `except: pass`): индекс говорит «снега нет» там, где прогноз не пришёл. У «Водителя» так же: гололёд и снегопад без прогноза — 0 | высокая: молчание источника читается нормой | И.3 |

## Что делаем

- **И.1.** Ночной минимум — минимум следующих суток прогноза. Так же «следующую ночь» берёт
  правило гололёда (`_ice_today` → `temp_min` завтрашних суток). `/ecology/status` отдаёт
  `night_min`, сервер и табло считают мороз по нему.
- **И.2.** Три уровня, как у РАГРАФ: Норма 0–2, Повышенная 3–5, Высокая 6–7. Регламент 1.3 —
  сеялка обновит копию на Volume. Сторож: каждый уровень достижим, и наибольшая сумма баллов не
  выше порога последнего уровня.
- **И.3.** Нет прогноза — снегопад и ночной минимум не величины (⊥): `snow_impact` и
  `night_min` равны null, а не 0.
  - «Погодная нагрузка» без обеих величин — без балла, с подписью «нет прогноза». С одной —
    балл по известной части и пометка «неполные данные».
  - «Водитель» без прогноза — балл по морозу и ветру с пометкой «неполные данные»: гололёд
    и снегопад не оценены.

## Решение: частичный балл — табло, ⊥ — регламенту

При неполных данных табло даёт балл по известной части с пометкой (`partial`, `missing`).
Регламент РАГРАФ в том же случае молчит: сумма с неизвестным слагаемым — ⊥. Это одна логика
для разных ролей (РАГРАФ, 18.11). Человек видит пометку и знает, чего не хватает. Регламенту
частичная сумма — только нижняя граница: вердикт по ней сменился бы с приходом недостающего,
а это нарушает сохранение вердикта (Теорема 1 отчёта РАГРАФ). Поэтому поле `missing` из ответа
не убирать: по нему регламент видит, какое слагаемое не пришло. Поле держат проверки
`TestСверкаРАГРАФ`.

## Чего не делаем сейчас

- **Уровень «Критическая» по норме** — например, ночь ниже расчётной температуры отопления
  Новосибирска −37 °C (СП 131.13330.2018). Это новое правило, а не исправление: сначала
  решение руководителя работы и сверка с РАГРАФ.
- **Прогулка** по-прежнему считает воздух по модели CAMS. Это предмет п. 9.5 отчёта о НИР, а не
  этого разбора.
